# 3Lines — website + CMS

The production website of **3Lines Advanced Technologies Company**, in English
and Arabic, and the CMS that manages it — one Next.js application, deployed to
Cloudflare Workers, live at **https://3lines.com.sa**.

- `README.md` (this file) — how the system works and how to develop on it
- [`docs/CMS-GUIDE.md`](docs/CMS-GUIDE.md) — the editor's manual for `/admin`
- [`docs/GOLIVE.md`](docs/GOLIVE.md) — the go-live runbook and the post-cutover verification record

## Architecture

```
                       ┌──────────────── edits ───────────────┐
                       ▼                                      │
   content/*.json  ◀── export ──  D1 database  ◀── writes ──  /admin  (password + signed session)
        │                              ▲
        │ build                        │ cf-prebuild.mjs exports remote D1 at build time
        ▼                              │
   ~50 prerendered pages (25 routes × EN/AR), served from Cloudflare's edge
```

- **Public pages are static.** Generated at build time from `content/*.json`;
  no database is queried when a visitor loads a page.
- **`/admin` writes to D1**, not to files. Media uploads go to R2.
- **Publish rebuilds the site.** The Publish button fires a
  `repository_dispatch` (event type `cms-publish`) at GitHub Actions, which
  rebuilds — the build exports the current D1 contents into `content/` — and
  deploys. An editor's Save is durable immediately; Publish makes it public.

**The byte-exact contract** underpins all of it: `npm run db:import:local`
followed by `node scripts/export-content.mjs` must leave `git diff content/`
empty. Every schema or exporter change must keep it so.

## Stack

Next.js 15 (App Router) · React · TypeScript · drizzle-orm on Cloudflare D1 ·
R2 for media · @opennextjs/cloudflare → Cloudflare Workers · GitHub Actions for
deploys · hand-authored CSS (no framework) · puppeteer-core driving the audit
harness.

## Repository layout

```
app/              Routes: app/[locale]/… is the public site, app/admin/… the CMS
components/       Renderers (blocks/, bodies/), chrome, admin UI components
lib/              Schema (blocks.ts), content loading, i18n, SEO, lib/admin/* write layer
content/          The exported content tree — generated from D1, do not hand-edit
public/assets/    CSS, JS, fonts, photography (hashed by the asset manifest)
scripts/          Audits, exporters, the build prelude, operator tools (all self-documenting)
drizzle/          D1 migrations (generated by drizzle-kit)
baseline/         Committed visual-regression reference; regenerating it is a reviewed act
source-content/   The original ingest inputs — historical bootstrap, see the warning below
deploy/           pm2 + nginx kit for self-hosting; NOT the deployment path (see docs/GOLIVE.md §6)
docs/             CMS-GUIDE.md (editor's manual) and GOLIVE.md (go-live record)
.github/          The deploy workflow (also lives on the default branch for Publish)
```

## Local development

```bash
npm install
cp .env.example .env.local            # then fill it in — see below
cp .dev.vars.example .dev.vars
npm run db:migrate:local              # create the local D1 schema
npm run db:import:local               # seed it from content/
npm run dev                           # site: http://localhost:3200/en
                                      # CMS:  http://localhost:3200/admin
```

Generate admin credentials rather than hand-writing them:

```bash
node scripts/admin-credentials.mjs secret
node scripts/admin-credentials.mjs password "<a long random password>"
```

> **Never run `npm run ingest` against a database that has CMS edits.** The
> ingest was the one-time bootstrap that built `content/` from the original
> source material. The CMS is now the source of truth, and both write to the
> same directory — re-running ingest reverts editor work. docs/GOLIVE.md §6 records
> the details.

### Environment variables

Names only — values are generated or secret. `.env.example` documents each one.

| Variable | Where | Purpose |
|---|---|---|
| `SITE_ORIGIN` | `.env.local` / Worker var | Canonical origin for sitemap, hreflang, JSON-LD |
| `SESSION_SECRET` | `.env.local` / Worker secret | HMAC key for the admin session cookie (≥32 chars) |
| `CMS_PASSWORD_HASH` | `.env.local` / Worker secret | PBKDF2 hash — never the password itself |
| `CONTACT_ENDPOINT` | `.env.local` / Worker var | Contact-form forward; the proxy fails closed without it |
| `GITHUB_DISPATCH_REPO` | Worker secret | `owner/repo` the Publish button dispatches to |
| `GITHUB_DISPATCH_TOKEN` | Worker secret | Token authorised to fire that dispatch |
| `CLOUDFLARE_D1_TOKEN` | GitHub Actions secret | Read D1 during the build's content export |
| `CLOUDFLARE_API_TOKEN` | GitHub Actions secret | Deploy the Worker |
| `CLOUDFLARE_ACCOUNT_ID` | GitHub Actions secret | The Cloudflare account |

Secrets go in via `wrangler secret put` piped with `printf '%s'` — a trailing
newline in a piped secret has already broken Publish once (the code also
`.trim()`s on read, belt and braces).

## The CMS

Everything an editor needs is CMS-managed: page copy, links, images,
statistics, section order, add/delete of sections and pages, page visibility,
navigation and footer, interface microcopy, shared bands, the news lifecycle
(card + article page created and deleted together), collections (services edits
mirror to the homepage grid), site info, and a fully deletable image library
guarded by a database reference check — an image that a page still uses refuses
to delete, so a deletion cannot break the site.

See [`docs/CMS-GUIDE.md`](docs/CMS-GUIDE.md) for the editor-facing manual.

Deliberately **not** CMS-editable: the single shared password (entropy-carried;
PBKDF2 capped at 100k iterations by the Workers runtime — see
`lib/admin/crypto.ts`), no undo/revisions, no SVG upload, contact-form field
names, and the ja/ko locales (seeded, disabled). Every image deletes from the
hosted CMS too: uploads instantly from R2, shipped assets as a one-commit
removal that rides the next deploy (~2 minutes, and the tile says so).

## Publish → production

```
Publish (two-click) ─▶ Worker ─▶ POST /repos/<GITHUB_DISPATCH_REPO>/dispatches
                                        │  event_type: cms-publish
                                        ▼
                      GitHub Actions (workflow on the DEFAULT branch,
                      pinned to build the production branch)
                                        │  cf:build — exports remote D1 → content/
                                        ▼
                      opennextjs-cloudflare deploy ─▶ 3lines.com.sa
```

The workflow also deploys on every push to the production branch
(`location-map-and-fixes`) and can be run manually from the Actions tab. The
deploy job is guarded to run only in the repository named `3lines-website`, so
the mirror repo never produces failed-run noise.

> **Do not deploy from Windows.** `wrangler deploy` crashes non-deterministically
> inside miniflare on Windows — sometimes after a partial upload — and CRLF
> produces different asset hashes than CI. GitHub Actions (Linux) is the only
> thing that ships. docs/GOLIVE.md §5 has the full story.

## Verification

```bash
npm run typecheck
npm run audit:content        # data ↔ schema ↔ renderers ↔ both locales
npm run audit:localization   # byte-exact round-trip, locale-invariant shared halves
npm run audit:links          # broken links, unreachable routes, orphans
npm run audit:console        # console errors, hydration, 4xx
npm run audit:a11y           # names, labels, headings, landmarks, contrast (WCAG AA)
npm run audit:rtl            # lang/dir, no letter-spaced Arabic, no overflow
npm run audit:manifest       # every shipped asset hash matches the manifest
AUDIT_MODE=baseline npm run audit:visual   # geometry diff vs the committed baseline
npm run baseline:update      # deliberate, reviewed baseline reset — never casual
```

`baseline/` is the committed reference for the visual audit;
`baseline/provenance.json` records when and from what it was captured. The
audit compares counts before geometry, never launders count mismatches into
geometry diffs, and requires `AUDIT_SELFTEST=1` to fabricate findings.

`scripts/audit-content.mjs` also asserts every piece of non-CMS copy appears in
a document of its own locale, every media reference resolves, and EN and AR
have identical block structure — losing content in a refactor is a build
failure, not a discovery.

## Internationalisation

- `app/[locale]/…` with `generateStaticParams` over `en`/`ar` and
  `dynamicParams = false`. `/` 307s to `/en`; unprefixed paths 308 to English.
- Content stores **locale-less route ids**; `lib/i18n.ts:localePath()` applies
  the prefix at render time, so the Arabic tree structurally cannot link into
  the English one.
- `public/assets/css/rtl.css` is scoped entirely to `[dir="rtl"]`/`:lang(ar)`,
  so the English rendering — and the committed baseline — are untouched by
  construction.
- Arabic uses self-hosted **Tajawal** (`scripts/fetch-fonts.mjs` documents how
  the font files were produced), is never letter-spaced, and pins headings to
  700 with `font-synthesis-weight: none` because Tajawal has no 600.
- The language switch is a prefix swap on the current path — it keeps the
  reader on the page they were reading, prerenders, and works without
  JavaScript.

## Things that will bite you

- **Never run `npm run build` while `next dev` is serving** — they share
  `.next` and the dev server starts 500ing until restarted.
- The local D1 sqlite file is keyed off `database_id` in `wrangler.jsonc`;
  changing that id silently points dev at a fresh empty database.
- D1 budgets roughly **50 queries per Worker invocation**, and Miniflare does
  not enforce it — a loop that queries per-item works locally and fails only in
  production. Write set-based SQL in `lib/admin/*`.
- The importer is a seeding tool: pages/blocks upsert by deterministic id, but
  settings, chrome and ui_strings are `ON CONFLICT DO NOTHING` — a re-import
  never reverts editor work, and re-running it against a structurally edited
  database is not supported.
- Shared bands align every copy on save — by design. A page that should differ
  is re-diverged afterwards through Pages & SEO.
- `scripts/audit-content.mjs` reads every quoted `case` label in the two
  renderer files as a declared block kind; don't add unrelated switches there.
- `audit:visual` without `AUDIT_MODE=baseline` diffs against the original
  Vercel source, which this project has outgrown; regression testing is the
  baseline mode.
- Read env vars **inside** request handlers, not at module scope — Cloudflare
  populates `process.env` per-request.

## Known limitations

- **The three legal pages are placeholder copy** (`status: placeholder`) —
  rendered `noindex`, dropped from the sitemap, and must not be switched
  visible until real text lands. An editorial task, in the CMS.
- The Arabic share card falls back to English copy: Satori cannot shape the
  self-hosted Arabic face from `.woff2`; shipping Tajawal as `.ttf` as well
  would fix it.
- The homepage partner marquee shows 18 of 39 logos with no "see all" —
  a design decision waiting on a human (`logos.total` exists in the schema).
- Per-user logins and revisions/undo are anticipated by the schema
  (`session.sub`) but not built.
- The contact form posts to a same-origin proxy (the upstream's CORS preflight
  rejects direct browser POSTs); the proxy fails closed with 503 when
  `CONTACT_ENDPOINT` is unset.
